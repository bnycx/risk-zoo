Portfolio Management & Risk Analytics

Risk Zoo

投资组合持仓管理与风险分析系统

录入持仓后，系统以真实行情与汇率完成估值，运行多类组合优化器给出权重、风险贡献与有效前沿，并把每一次计算留成可预览、可下载、可复核的底稿。

Python 计算内核 Cloudflare Workers 网关 SQLite 持久化 原生 JS + Chart.js 契约化开发文档

01项目概览

系统由三条相互衔接的业务链构成：先得到可信的当前估值，再在估值结果上做组合优化，最后把整个过程固化为可复核的计算底稿。三条链各自有明确的数据真源，任何一步不成功都不会被当作成功结果持久化。

01 / INPUT持仓录入编辑并保存资产权重；游客看到示例状态，登录用户的数据持久化到后端。
02 / VALUATION当前估值取真实行情与汇率，按六阶段编排计算市值与分布；仅完整成功的结果成为快照真源。
03 / OPTIMIZATION组合优化在统一历史样本上运行五类正式优化器，产出权重、风险贡献与有效前沿。
04 / TRACE底稿与复用计算底稿可预览、复制、下载；结果可提问、可分析，刷新后按严格读取规则恢复。
三类主体：游客使用示例状态且不写个人数据；登录用户拥有持久化持仓、估值快照与历史净值；管理员使用独立入口查看只读运营摘要。

02核心能力

面向"看清楚组合现在是什么样、以及可以变成什么样"这两个问题，系统提供从数据到解释的完整闭环。

HOLDINGS

持仓管理

录入、编辑并保存持仓，支持刷新后的状态恢复与游客/账号隔离。

VALUATION

当前估值

以真实行情与汇率计算市值、资产分布与组合概览，完整成功后才保存快照。

OPTIMIZER

组合优化

五类正式优化器、权重对比表、风险贡献分解与有效前沿同图呈现。

WORKPAPER

计算底稿

每次计算生成带校验值的结构化底稿，可预览、复制、下载，并在刷新后恢复。

HISTORY

历史净值

登录用户的组合总市值曲线，按统一币种口径呈现。

ASSISTANT

结果提问

针对当前计算结果提问，回答边界受上下文与安全规则约束。

03系统架构

静态前端与计算后端分层部署，身份校验与限流在边缘完成，可信身份只在后端生效。各层之间通过明确的 HTTP 契约连接。

BROWSER
浏览器

静态页面、图表渲染与交互；同源相对路径调用 /api/*。

↓
EDGE / STATIC
Cloudflare Pages + Pages Function

托管静态资源；Pages Function 对 API 请求做透明反向代理。

↓
GATEWAY
Cloudflare Worker

校验身份令牌、执行限流与额度策略、转发请求；外部不可信输入在此被拦截。

↓
COMPUTE
Python 后端容器

估值编排、优化求解、底稿构建与持久化；业务数据落在 SQLite，市场数据独立缓存。

↓
IDENTITY
Firebase 认证

令牌在边缘校验，用户标识向下游传递；后端只接受已验证的可信身份。

信任边界：公开前端只承载展示与输入；身份判定、额度扣减与业务写入都在网关和后端完成。管理员入口与用户主站分离，权限独立判定。

04计算口径

优化器的数量与归属容易被误读，以下口径与系统内部正式契约一致。

正式优化器（5 类）Draft 中的 run entries说明
Classic MV2最大夏普与最小方差两个目标
Factor MV2最大夏普与最小波动两个目标
NCO1非线性约束优化
Risk Parity1等风险预算
HRP1层次风险平价，含树状结构展示
合计 7 个 run/result entries5 类优化器 + 2 个额外目标条目
有效前沿不是第六个优化器。它由 Classic MV 在不同风险—收益取舍下生成，属于可视化结果；在底稿中位于 visualization 区块，不生成独立的 fitted 产物。对外统一说"5 类正式优化器 / 7 个 Draft run entries"。

四件事决定结果是否可信

SAME FIT

同次拟合

五类求解器共用本次运行中已拟合的估计量，不二次拟合以提取产物。

COMPLETE ONLY

完整才保存

HTTP 200 不等于业务成功；只有完整成功的结果才覆盖数据真源。

STRICT READ

严格读取

底稿与快照按固定字段集合读取，校验值不符即视为不可用。

PARTIAL FAILURE

部分失败有语义

局部成功（例如前沿生成失败）被单独分类，不会伪装成完整成功。

市场数据与汇率

行情来自外部数据源并写入独立缓存；汇率以主货币对为基准，跨币种折算通过基准货币桥接，避免直连交叉对带来的误差。报价货币与报价单位分开处理，原始报价单位按比例换算为结算货币。

05工程与质量

项目采用"先文档、后编码"的契约化开发方式：正式裁决写入开发文档，代码描述当前实现，二者不一致时以文档为准并重新裁决。

CONTRACT

契约化文档

正式契约、当前实现、已知限制、退役架构与未取证内容使用固定标记，避免计划与现状混淆。

TEST

多层测试

Python 单元测试与 Node 测试覆盖后端、Worker、前端合同与部署路径矩阵。

HEALTH

代码健康门禁

函数规模、复杂度、文件体积与变更回归均有检查；超线由职责拆分解决，不放宽阈值。

DETERMINISM

确定性验证

关键计算以不同哈希种子的独立进程做逐字节比对，避免顺序与哈希随机性影响结果。

DEPLOY

部署校验

推送成功不等于发布完成；部署流水线的检查结果必须逐项确认，烟雾检查拦截异常版本。

PRIVACY

数据最小化

凭据不入库、不写前端；日志脱敏；游客数据不写入任何账户。

06常见问题

这是投资建议工具吗？

不是。系统提供持仓管理、估值与组合分析能力，所有展示结果仅用于研究与演示，不构成任何投资建议。

游客看到的数据是真实的吗？

不是。游客状态是示例数据，不对应任何账户，也不会写入个人账户数据。

为什么有时估值结果没有被保存？

只有完整成功的计算才会成为快照真源。行情缺失、历史样本不足或局部失败都会被明确分类，不会用不完整结果覆盖已有数据。

有效前沿算第六个优化器吗？

不算。它是 Classic MV 在不同风险—收益取舍下生成的可视化结果，不属于优化器清单。

为什么优化器结果是 7 项而不是 5 项？

产品有 5 类正式优化器；其中 Classic MV 与 Factor MV 各包含两个目标条目，因此底稿保存 7 个 run/result entries。两者是不同层级的概念。

行情和汇率会有延迟吗？

会。数据来自外部源并经过缓存，可能因上游限制或缓存状态出现延迟或缺失；系统对此有明确的降级与状态分类。
